## Modelo de datos (SCRUM-122)

Definido en `shared/performedSets.ts` y compartido por la API y la web.

```ts
type PerformedSet = {
  id: string;          // UUID asignado por el servidor
  itemId: string;      // RoutineItem.id del ejercicio dentro de la sesión
  setNumber: number;   // 1, 2, 3… por ejercicio; lo asigna el servidor
  repetitions: number;
  weightKg: number;
  rpe: number;
  recordedAt: string;  // ISO 8601
};
```

La sesión activa (`shared/trainingSessions.ts`) incorpora `performedSets?: PerformedSet[]`. El campo es **opcional** para que las sesiones guardadas antes de HU03 sigan siendo válidas. La rutina copiada en la sesión no se modifica: los valores planificados y los reales se guardan por separado.

### Límites de validación

Constantes en `PERFORMED_SET_LIMITS`, reutilizadas por el formulario:

| Campo | Mínimo | Máximo | Paso | Nota |
| :--- | :---: | :---: | :---: | :--- |
| Repeticiones | 1 | 100 | 1 | Entero |
| Peso (kg) | 0 | 500 | 0,5 | 0 kg = ejercicio con peso corporal |
| RPE | 1 | 10 | 0,5 | Escala de esfuerzo percibido |

> Pendiente de confirmar por el PO (Joaquín). La rutina planifica RIR, no RPE; como referencia, RPE ≈ 10 − RIR.

## API (SCRUM-123)

`POST /sessions/active/sets` (también bajo `/api`)

```json
{ "itemId": "demo-sentadilla", "repetitions": 8, "weightKg": 62.5, "rpe": 9 }
```

| Respuesta | Caso |
| :---: | :--- |
| 201 | Serie guardada. Devuelve la `PerformedSet` con `id`, `setNumber` y `recordedAt`. |
| 400 | Valores fuera de límites, de tipo incorrecto, JSON no válido o ejercicio que no pertenece a la sesión. |
| 404 | No hay ninguna sesión en curso. |
| 500 | Error al leer o guardar el archivo de sesión. |

`GET /sessions/active` devuelve la sesión con sus `performedSets`.

La escritura usa la misma transacción por archivo y escritura atómica que el resto de la API (`api/src/jsonStorage.ts`). Dos series enviadas a la vez se guardan ambas con números distintos.
